# Repeatable combat encounter

Run from the Westford system directory:

```sh
npm run test:combat
npm run combat:report
```

The report command runs the same five-test Vitest encounter and writes `output/combat-encounter/report.json` only after every assertion and identical replay pass. Reports are written through a candidate file; a failed run removes the candidate and leaves the last successful report in place. The default seed is `1592594996` (`0x5eed1234`). To explore another deterministic encounter, use `OSP_COMBAT_SEED=123 npm run combat:report`. An alternate seed must still satisfy the scenario's coverage checks (both hits and misses, enemy action, multiple rounds and a terminal result); some seeds may fail those checks. A failed encounter includes its seed and action trace in the test error. A round cap fails rather than reporting a stalled encounter as success.

## Isolation and actual character data

Normal tests read only the frozen JSON fixture, never a live database or Foundry session. Each run deep-copies the fixture. Actor, combatant, chat and settings writes go to in-memory adapters. The test checks fixture immutability, completed authority operations, and disposal after success and after an intentional round-limit failure. No `src/`, deployed `dist/`, campaign documents, clocks or settings are changed. No deployment or live-page reload is needed for these test-only files.

The fixture contains actual Westford actor records and their separately stored embedded items, plus minimal user assignments and source hashes. Party eligibility means assigned to a user or owned by a non-GM user, with usable positive current/maximum HP. Report format v5 preserves the current three-player snapshot: Blayne “Slim” Isembart, Fung Telt and Myr Ragmussen. Edvin’s assigned record has incomplete HP and is explicitly excluded; stale assignments without matching actors are included in the report. This test does not invent or repair campaign stats.

To deliberately refresh the snapshot from current campaign data:

```sh
node scripts/capture-combat-party.js
```

The capture script hashes actors and users files, copies both databases into disposable temporary directories, checks identical copied bytes and stable source file sets, and opens **only the copies**. It rechecks source hashes before publishing the fixture atomically. If the campaign changes during capture, it fails and should be retried while idle. Only the fixture is replaced. The installed native LevelDB binary is copied to a temporary library directory to avoid macOS `._` metadata being selected as a native library; dependencies are not edited.

## What the encounter checks

- Production `OspActor` character preparation derives levels, armor class and saves from the copied data/equipment.
- Production `OspCombat` starts combat, rolls/sorts initiative and advances legal turns/rounds without repeated turns.
- Production `ItemHandler.rollWeapon` uses each copied actor's equipped weapon when one is available (the current eligible party includes Myr Ragmussen's Warhammer, `1d4+1`); actors without an equipped weapon use the production unarmed path. It spends attack reservations, applies weapon policy, resolves hits/misses/critical rolls and generates damage cards.
- The copied actor preparation is checked against the current derived AC values: Blayne 17, Fung 10 and Myr 17. Myr's equipped armor is then temporarily removed from the isolated copy and recalculated to prove the actual armor changes AAC before the original copied equipment is restored.
- Controlled probes independently assert the copied Warhammer's normal damage (`1d4+1+1`, fixed result 5), an armored AAC boundary (same roll misses AC 17 and hits stripped AC 12), and a natural-20 against AC 100 resolved by the production critical table (fixed d100 50, doubled `2d4+1+1`, result 7). A critical reroll-ones probe also confirms the production critical result changes damage to 8. These probes apply damage through the production health authority.
- Production progression, critical and health authorities use the in-memory chat transport and write only copied documents. HP deltas and attack outcomes are checked against the rolls.
- A seeded opponent is chosen from three synthetic sparring profiles. The encounter uses the actual weapon declaration and speed 4 for Myr's Warhammer, with unarmed fallback for actors without an equipped weapon; both sides perform one melee action per turn until one side cannot continue.
- Defeated combatants are marked and ineligible; the encounter reaches a terminal outcome within 30 rounds. Two fresh runs must have identical initiative, action traces and final HP.
- The supplemental spell scenario uses the three actual Myr scrolls: Hold Person (`DybpvO1h6TGhiy8t`, cleric level 2), Cure Light Wounds (`NKofRGr0sjMzpSnN`, cleric level 1), and reversed Cause Fear (`0TRlfSBclXzcCjwL`, `remove_fear`, cleric level 1). It verifies canonical links, quantity 1→0, spell cards and completed receipts, exact replay idempotence, and rejection after exhaustion. Wild-magic checks are forced to 10 (Normal), 20 (Boon), and 1 (Bane); Bane consumes the source and does not automatically fail the spell. The report distinguishes actual prepared/known spell flags from the absence of `type: "spell"` item documents: Fung has migrated `memorizedSpells` for Glamour, while Slim has no spell source; a prepared Glamour cast is rejected for its missing Wand/Staff focus without changing slots or rolling.
- Saving throws run through production `OspDice.RollSave`/`sendRoll`/`digestResult`, with adapters only for Foundry dice and rendering. Myr's tested boundaries include spell 13, plain nonmagical spell 15, Hold Person’s single −2 target 15, magical paralysis 12, plain death 11, and incapacitated magical spell 17. Slim uses his actual Half-Orc class table: spells 15, wands 14, plain death 13. Fung's Gnome resilience gives spells 12 and wands 11; plain death is 13 and death against a spell source is 10. Each boundary is checked with controlled success and failure rolls. The current spell authority leaves target effects to the GM, so Hold Person paralysis and Cause Fear fleeing are not auto-applied.
- Status transitions use the production health authority. Incapacitated alone and Unconscious alone block casting without spending a scroll or rolling; they enforce prone/helpless and stand-up restrictions. Clearing the conditions restores acting. Cure Light Wounds is followed by an explicit scripted GM healing step on a copied injured Fung (catalog d6+1, fixed d6=4, total 5 capped at maximum); casting itself does not heal targets.
- The movement probe runs after copied actor preparation and records actual IDs, names, Strength, race, inventory-derived weight, and movement. Its independent fixture goldens are Slim tactical 40/overland 120 (unencumbered), Fung 20/60 (light), and Myr 30/90 (light). A copied actual weapon is used as the controlled load adapter with `unitWeight=1`: quantity `Strength × 15` reaches the exact heavy boundary, while `Strength × 15 + 1` is overloaded and reduces tactical movement to 0. It also invokes the production `TokenRulerOSP` with an isolated Foundry base adapter: exact tactical/overland budget returns the base style, and budget +1 returns red `{color: 0x990000, alpha: 0.4}`. This covers speed, encumbrance and ruler colors only; token position, wall collision and actual move-budget enforcement are not simulated.
- The ranged/reaction probe uses Myr's actual Sling (`9OyrBZddiPG0g4dw`) and Sling Stone stack (`63c4zCkhvUfdKcnm`, original quantity 20), with only copied Sling equip/Warhammer unequip changes. It calls production `ItemHandler.rollWeapon` and the real `confirmAttackContext` through a dialog-choice adapter, checking short/medium/long modifiers (+1/0/-1), half cover −2, GM-confirmed Defender −2, out-of-range/full-cover/opponent-in-melee blocking, canceled prompt and canceled die-roll reservation release, and no-spend/no-ammo behavior. All 20 stones are expended on hits or misses without replenishment; the empty stack is removed from the copied collection while the copied launcher remains. Fung's actual Oil Flask is also copied/equipped and self-consumed: production 2d6 rolls are fixed at 12 and the non-proficiency damage cap is checked at 4. Unsupported automatic opportunity attacks, interception and automatic reaction attacks remain explicitly out of scope.
- Supported reaction effects use the production combat-effect authority: Aim forgoes the current attack, grants +2 to the next attack, expires, and rejects a late declaration; Parry/Dodge forgoes the owner's attack and applies −2 to the same-round attacker, then expires; Charge grants +2 melee and applies the target-charging +1 modifier, then expires and is cleared. Foreign-combat effects are rejected. Defender is GM-confirmed context, not a new talent. Range/cover and charge's 20-foot straight-line geometry, plus Aim/Parry movement-forgo restrictions, are GM confirmations rather than measured path proof. Persistent Oil Flask fire damage remains manual/future.

## Scope

This is a mechanics integration regression test, not a Foundry browser/end-to-end test. It uses neutral combat-context choices and seeded dice in place of dialogs and physical/random dice. It exercises the copied Warhammer and unarmed fallback, plus Myr's copied Sling/ammunition and Fung's copied Oil Flask; the assigned Edvin Shortbow remains excluded because that actor has incomplete HP. No fake actor HP or new weapon source is introduced.

The supplemental spell scenario uses actual Myr scroll sources and the copied cleric focus policy; it does not add prepared spell items or require a fabricated Holy Symbol setup. It runs on active copied combatant turns and records each source, spell key, reverse form, level, quantity, wild result, save result and status transition. Prepared/known availability is reported per character, including Fung’s migrated Glamour state and Slim’s lack of spell sources; no actual damage spell source is available in the eligible party. The production spell authority deliberately leaves target saves and target effects to the GM; the test records that boundary instead of inventing automatic Hold Person paralysis, Cause Fear fleeing, or Cure Light Wounds target application. Status checks use the production health authority for Incapacitated, Unconscious and Prone, including cast blocking, save penalties, helplessness, and stand-up restrictions. Critical table cards follow the production implementation, including its requirement for manual GM adjudication of injury effects.

Foundry document storage, sanitization, UI and core combat deletion hooks are adapters. Cleanup checks establish disposal of the isolated test state and absence of pending system operations, not that core Foundry deletion hooks work. Existing focused tests remain necessary alongside this encounter.
